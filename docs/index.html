Caldera Sonos Bridge

Play Plex music to Sonos, from Plexamp

Every Sonos room in the house appears in Plexamp as its own player. Pick one, and your Plex library plays on that speaker. Audio streams straight from your Plex server to the speaker — the bridge never touches it.

v0.1.1 Docker GPL-3.0 Sonos only

Why this exists

Plex used to play to Sonos itself. As of a few days ago it stopped.

The official route is gone. Plex's own Sonos integration — the one you set up through your Plex account — has stopped working, and it is not the only service to have dropped Sonos support. That left a good Plex library and a house full of Sonos speakers with nothing joining them. This bridge is that join, and it depends on nothing but your own network: your Plex server, your speakers, and a small daemon on a machine you own.

How it works

Plexamp cannot cast to a Sonos speaker, but it can cast to a Plex player. The bridge is one of those per room.

Plexampphone, desktop or web
→
the bridgeone Plex player per room
→
Sonosyour rooms

Audio does not follow that path. The bridge hands each speaker a URL and Sonos fetches the music straight from your Plex server — no extra hop, nothing re-encoded on the way through, and nothing for the bridge to be a bottleneck for.

🎵Bit-perfect where it can be

16/44.1, 16/48, 24/44.1 and 24/48 reach the speaker exactly as Plex stores them. Anything above 24/48 is brought down to 24/48 by your server and stays lossless.

⏭Gapless playback

A window of the Plex queue is loaded onto the speaker, which moves between tracks itself. Skips are instant rather than a round trip.

🔊Group-aware transport

Playing to a grouped room plays to the group, as Sonos does. Volume and mute stay with the individual speaker.

📡Live state

Pause from the Sonos app and Plexamp's now-playing screen follows. Progress goes back to your server, so play counts and resume points work.

🖥Settings page

A page on port 32700 shows every room, what it is doing, and the settings you can change — without rewriting the docker run line.

🏷Stable devices

Each room is a separate player with an identity that survives restarts, so Plexamp remembers your speakers.

Install with Docker

On an always-on Linux machine on the same network as your speakers — a NAS, a Raspberry Pi, a home server.

docker run -d \
  --name caldera-sonos-bridge \
  --network host \
  --restart unless-stopped \
  -v caldera-sonos:/config \
  ghcr.io/meltface-80/caldera-sonos-bridge:latest
--network host is required. Plex finds players by multicast, and multicast does not cross Docker's default bridge network. It is also how the bridge finds your speakers. Docker Desktop for macOS and Windows has no real host networking, so this needs a Linux host.
Keep the volume. /config holds your Plex token, your settings and the port each room was given. Without it you re-link after every image pull.
  1. Open http://<host-ip>:32700/ — the settings page lists the Sonos rooms it found.
  2. Click Link a Plex account and enter the four-character code at plex.tv/link.
  3. Open Plexamp. Your rooms are in the list of things to play to.

Linking is only needed for Plexamp on a phone, which finds players through your account rather than over the network. Desktop Plexamp and Plex Web find the rooms without it. Playback always goes straight to the bridge over your own network.

Updates from the settings page

The page says which version is running and whether a newer image has been published — and installs it. No shell, no re-running the docker run line.

docker run -d \
  --name caldera-sonos-bridge \
  --network host \
  --restart unless-stopped \
  -v caldera-sonos:/config \
  -v /var/run/docker.sock:/var/run/docker.sock \
  ghcr.io/meltface-80/caldera-sonos-bridge:latest
Weigh that up. The extra mount is what lets the container replace itself, and access to the Docker socket is effectively root on the host. It is not in the default command for that reason. Without it the bridge still tells you an update exists; it just cannot install one, and the page says so rather than offering a button that would fail.
  1. Install update pulls the new image and builds a container from your existing one's exact configuration — same environment, same volumes, same network.
  2. It hands over the ports and exits. Your settings, Plex link and room ports are in the config volume, so they carry across.
  3. If the new container cannot be created or will not start, the old one is put back under its own name and restarts on the previous image.
  4. Tick Install updates automatically to check every six hours and apply what it finds.

Environment variables

All optional; pass any with -e NAME=value. Most can also be changed on the settings page, which then takes precedence.

VariableDefaultPurpose
NAME_SUFFIX" (Sonos)"Appended to each room name in Plexamp. Empty for bare room names.
HTTP_PORT32700Port for the settings page.
PLAYER_PORT_BASE32701First port for the per-room players. Plex's own ports are skipped.
SONOS_HOSTS—A player's IP, for when multicast discovery is unreliable. One is enough.
INCLUDE_ZONES—Publish only these rooms, e.g. Kitchen,Study.
EXCLUDE_ZONES—Publish everything except these rooms.
STREAM_FORMAToriginalBit-perfect within 24/48, resampled above it. flac or mp3 transcode everything.
VOLUME_LIMIT100What Plex's slider at 100% sets the speaker to.
UNGROUP_ON_PLAYfalseDetach a room from its Sonos group before playing to it.
BRIDGE_MODEqueuequeue for gapless playback; direct loads each track onto the transport.
AUTO_UPDATEfalseInstall a newer image when one appears, without asking.
UPDATE_CHECKtrueLook for newer images at all.
LOG_LEVELINFODEBUG logs every Plex command and Sonos action.

Troubleshooting

Start at http://<host-ip>:32700/, which shows what the bridge can see.

No rooms

The table is empty

The bridge has found no players. Check the container really is on host networking and shares a subnet with the speakers. Setting SONOS_HOSTS to one player's IP skips discovery entirely.

Not in Plexamp

Rooms listed, but nothing to cast to

On a phone, check the On Plex column says published. On a desktop it is the multicast path — same subnet, and watch for IGMP snooping or "multicast enhancement" on routers and access points.

Silence

Playback starts then stops

Usually a format Sonos will not take. Run with LOG_LEVEL=DEBUG and look for UPnP error 714, or set STREAM_FORMAT=mp3 to confirm it is the format rather than the plumbing.

Everywhere

One room plays in all of them

The room is grouped in the Sonos app, and transport commands belong to the group coordinator. Ungroup it, or set UNGROUP_ON_PLAY=true.
